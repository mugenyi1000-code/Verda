# Verda design system

This is the design system the running app already uses. It is written to be
handed to someone — or pasted into a builder like Lovable, v0 or Figma Make —
and produce screens that sit alongside Verda's rather than beside them.

Everything below is lifted from `app/styles.css`. Where the two ever disagree,
the stylesheet is right and this file is stale.

The canvas of hi-fi artboards built from this system lives in `design/`
(`design/artboards/*.dc.html`, regenerated by `node design/build-artboards.mjs`).

---

## 0. What the product is, in one paragraph

Verda is environmental, health and safety compliance monitoring for industrial
sites — mines, quarries, factories, construction — in Uganda, Kenya, Tanzania,
DR Congo and Zambia. Its users are E&S consultants and site SHE officers
producing lender-mandated monthly reports (ESSRs), running audits and
inspections, and tracking permits that expire. **The screens are scanned and
operated, not read.** That single fact sets everything that follows:
information design over decoration, state readable at a glance, figures that
line up in a column, and elevation spent only where something genuinely floats.

Themes switch on `<html data-theme="forest|ocean|amber|slate">`.

**Charts and status** use a separate, fixed palette — categorical slots 1–3 and
four status steps, never brand colours:

```
--chart-1:#2a78d6  --chart-2:#eb6834  --chart-3:#1baf7a
--chart-good:#0ca30c  --chart-warning:#fab219  --chart-serious:#ec835a  --chart-critical:#d03b3b
```

**Rule: colour is never the only signal.** A status badge carries a dot and a
word. An overdue table row carries a left stripe as well as a tint. Every chart
bar is directly value-labelled and every multi-series chart carries a legend.
All three survive a greyscale print and a colour-blind reader; a pink row does
not.

## 2. Type

Two faces, one job each.

- **IBM Plex Sans** — the interface.
- **IBM Plex Mono** — anything that is a *measurement or a reference*:
  coordinates, permit numbers, m³, kWh, LTIFR, dates in tables, document
  references. An ESSR is mostly readings, and readings have to line up in a
  column and read like instrument output rather than prose. Always with
  `font-variant-numeric: tabular-nums`.

| Role | Size | Weight | Tracking | Line |
|---|---|---|---|---|
| h1 | 1.95rem | 600 | −0.021em | 1.15 |
| h2 | 1.4rem | 600 | −0.015em | 1.2 |
| h3 | 1.06rem | 600 | −0.008em | 1.3 |
| h4 | 0.96rem | 600 | −0.005em | 1.35 |
| body | 14px | 400 | — | 1.55, max 74ch |
| `.small` | 0.82rem | 400 | — | — |
| eyebrow / table head | 0.7rem | 600 | +0.07em, uppercase | — |
| figure (`.stat`, `.kpi-value`) | 1.6–1.85rem | **500**, Mono | −0.045em | 1.1 |

Big figures are set at weight 500, not 700 — a large number does not need to
shout to be found.

## 3. Shape, elevation, spacing

Radius by role, because a control, a card and a feature panel are different
objects: `--r-control: 7px`, `--r-card: 12px`, `--r-feature: 16px`,
`--r-pill: 999px`.

Elevation by role, not by habit:

| Token | Value | Used by |
|---|---|---|
| `--shadow-raise` | `0 1px 2px rgba(15,30,22,.05)` | resting cards, sparingly |
| `--shadow-float` | `0 10px 28px rgba(15,30,22,.10), 0 2px 8px rgba(15,30,22,.06)` | **the generated document preview and the recommended plan — nothing else** |
| `--shadow-modal` | `0 24px 60px rgba(10,20,15,.26), 0 6px 18px rgba(10,20,15,.12)` | dialogs |

**Most surfaces get a hairline border and no shadow.** A shadow means "this
floats above the page", which is true of a modal and of the generated report,
and of nothing else on a working screen.

Spacing rhythm: `4 · 8 · 12 · 16 · 24 · 32 · 48`. Content column caps at
1120px. Sidebar is 258px. Top bar is 58px and sticky.

Motion is deliberately thin: 120–160 ms, on colour and border only, and every
transition is disabled under `prefers-reduced-motion`. Nothing slides; nothing
bounces.

## 4. Components

**Card** — `background: --surface; border: 1px solid --border; border-radius:
12px; padding: 18px 20px`. No shadow.

**Button** — 9px/16px, radius 7px, weight 500, 8px gap to its icon.
`.btn-primary` fills `--solid-1` with white text at weight 600; `.btn-ghost` is
transparent; `.btn-sm` is 5px/11px at 0.79rem. Hover moves background to
`--surface-2` and border to `--brand-2`. Focus is `2px solid --brand-2` with a
2px offset — never removed.

**Input** — 9px/11px, radius 7px, 1px `--border`. Focus: border `--brand-1`
plus a 3px `--ring` halo. Invalid: border `--warn` over a 8% `--warn` wash,
with a message that says what to do next. **Computed (carried-forward) cells**
sit on `--brand-3` at weight 700 and are not editable — the tint is how a user
learns which figures Verda owns.

**Table** — head is 0.7rem uppercase on `--surface-2` with a `--border` rule;
rows separate with a 1px `--line`; hover moves to `--surface-2`. Numeric
columns take `.num` (Mono, tabular, right-aligned). Overdue rows take
`.row-overdue`: a 6% `--warn` wash plus `inset 3px 0 0 --warn`. Wide tables
scroll inside their own container, never the page body.

**Badge** — pill on a tint, 0.72rem/600, with a 6px dot in `currentColor`
before the label. Four status variants: good, warning, serious, critical.

**Tabs** — one segmented control: a `--surface-2` track with a 3px pad, and a
single lifted `--surface` selection. Not a row of independent buttons that each
look chosen.

**KPI tile** — a card with a 3px left border in the status colour, a Mono
figure at 1.6rem/500, an uppercase label, and a sub-line naming what the figure
is. The colour is a supporting cue; the tile still reads in greyscale.

**Nav item** — active state is a selected row in a list, not a floating button:
`--brand-3` ground, `--brand-1` text, a 3px left rail, weight 600. No shadow.

**Empty state** — the module's own illustration, one sentence naming the next
action, and the button that starts it. An empty table is the first thing a new
user sees on half these screens; a line of grey text tells them nothing.

**Illustrations** — 17 original flat SVGs (pits and headframes, wetlands, crews,
wildlife), filled from theme tokens so they re-colour with the theme. No stock
photography and nothing hotlinked, so they work offline.

**Icons** — a single inline SVG set on a 24-grid, `stroke-width: 1.7`, round
caps and joins, 18px in nav and 17px in buttons. Never a second icon family.

## 5. Page patterns

**Shell** — sticky top bar (brand · credits pill · jurisdiction, language and
theme selects · user) over a two-column layout: 258px sidebar grouped
Monitor / Manage / Grow, and a content column.

**Page header** — title and a one-line lead on a `115deg` `--brand-3`
gradient, with the module illustration at 150×92 on the right, in a
16px-radius panel.

**Report section (the ESSR pattern)** — every section is three blocks in the
same order: **tables → photographs → narrative**, under a collapsible guide box
(what this section is for / how to fill it in / a worked example). Same order in
every one of the 23 sections, so the tenth is learned from the first.

**Data-entry table** — compact inputs inside a `--surface-2` panel, a computed
cumulative column the user cannot type into, and a note saying which report the
figures were carried forward from.

**Drop zone** — 1.5px dashed, `--surface-2`, going to `--brand-3` with a
`--brand-1` border when a file is over it. Images are downscaled in the browser
before they are stored.

**Phone width (≤620px)** — the top bar wraps rather than pushing the page
sideways, the sidebar is hidden, and content padding drops to 18px/16px. The
field-capture screen is three fields and a photograph: a form with fourteen
fields gets filled in from memory at the end of the shift.

## 6. Rules worth restating to any builder

1. **Colour is never the only signal.** Dot, word, stripe, value label.
2. **Elevation is a claim.** If it does not float above the page, it gets a
   hairline border and no shadow.
3. **Figures are Mono, tabular and right-aligned.** Columns of numbers that do
   not align defeat the point of setting them in a data face.
4. **A computed figure looks computed.** The carried-forward tint is a
   promise: Verda owns this number, you will never key it twice.
5. **Every rate shows its formula and its denominator** on screen. A rate a
   lender cannot reproduce is a rate they will not accept.
6. **Invalid input is explained, not swallowed**, and the message says what to
   do next.
7. **One accent per screen.** `--accent` is for the single thing that must be
   noticed, usually a caveat.
8. **Focus is never removed** — 2px `--brand-2`, 2px offset, everywhere.

## 7. Using this with Lovable (or any prompt-driven builder)

Paste sections 1–6 as the project's design brief, then add:

> Build with these tokens as CSS custom properties on `:root`, with the three
> alternate themes under `[data-theme="…"]` selectors. Use IBM Plex Sans and
> IBM Plex Mono from Google Fonts. Do not introduce a second icon family, a
> shadow on a resting card, or a status that is signalled by colour alone.

Two cautions, so nothing has to be unwound later:

- **Verda is a static, no-backend app** (`localStorage`, key `verda_state_v2`).
  A builder will reach for a backend by default. If you let it, auth, tenancy
  and billing become real work, not a prototype — decide that deliberately.
- **The drafting engine is a documented deterministic template engine, not a
  live model call.** `app/ai.js` says so in its header and the README says so
  too. Keep any generated marketing copy equally honest; an acquirer's
  technical diligence opens that file.
